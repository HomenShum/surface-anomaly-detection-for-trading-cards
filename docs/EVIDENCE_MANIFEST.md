# Evidence Manifest

Card Condition Vault inference responses include a SHA-256 evidence manifest so reports can be traced back to the exact bytes used by the API.

## Manifest fields

- `manifest_version`: Manifest schema version. Current value is `1.0`.
- `report_id`: Stable report identifier. Callers may provide one for analyze and compare flows.
- `created_at`: UTC timestamp generated by the API.
- `items`: Evidence entries for source and derived artifacts.
- `manifest_sha256`: SHA-256 hash of the canonical manifest payload, excluding `created_at` and `manifest_sha256`.

## Evidence item fields

- `name`: Logical artifact name, such as `source`, `normalized`, `baseline_source`, or `candidate_source`.
- `sha256`: SHA-256 hash of the artifact bytes.
- `content_type`: MIME type supplied by the caller, or `application/octet-stream`.
- `size_bytes`: Artifact size in bytes.
- `uri`: Optional external evidence location.
- `metadata`: Optional structured details such as original filename or normalizer metadata.

## API coverage

- `POST /scan/normalize` returns normalized image evidence and a manifest for source and normalized bytes.
- `POST /scan/analyze` returns normalized image evidence plus a report JSON object with findings, score, and manifest.
- `POST /scan/compare` returns baseline/candidate normalized evidence plus a comparison report and manifest.

If project-specific normalizer or detector modules are unavailable, the service uses deterministic fallbacks and records normalization fallback warnings in the normalized scan payload.
